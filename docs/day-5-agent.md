# 久坐活动助手 v1 · Agent 交互说明

## 职责边界

Agent 只负责**理解和挑选**，不负责**计算和落库**：

| 做 | 不做 |
| --- | --- |
| 读设置、读今日安排 | 直接写库 |
| 把「下午要开会，帮我重新排」翻译成参数 | 编造工具没返回的时间 |
| 解释「推迟到了几点、为什么是这点」 | 给医疗/运动处方类建议 |
| 信息不足时先追问 | 谎称「已经帮你安排好了」 |

## 三个只读工具

工具签名里**没有 user_id**——身份来自登录校验写入的 ContextVar，模型无法越权。

| 工具 | 入参 | 返回 |
| --- | --- | --- |
| `get_my_activity_settings` | — | 工作时段、可活动窗口、免打扰、每天次数 |
| `list_my_activities` | `date`（默认今天） | 当天各条时间/状态 + 计数汇总 |
| `preview_schedule` | `daily_target`、`from_time` | 后端算好的候选时间槽 |

`preview_schedule` 只读：调用排期算法返回结果，不插库。**时间永远由后端算，模型只挑选。**

## 两条交互链路

### 链路 A：对话里问（CopilotKit / AG-UI）

```
用户在 /assistant 说「下午两点到四点开会，帮我重新安排」
  -> Agent 调 preview_schedule(from_time="16:00")
  -> 后端算槽、校验免打扰 -> 返回候选时间
  -> 模型用自然语言复述候选，并提示到活动页「生成建议」确认
```

### 链路 B：活动页的建议卡片（REST）

```
活动页点「生成建议」
  -> POST /activity/agent/suggest（后端算槽，不落库）
  -> 前端渲染成建议卡片
  -> 用户点「确认保存全部」
  -> POST /activity/agent/confirm（后端逐条二次校验后落库）
```

## 关键安全点

1. **confirm 二次校验**：前端传回的每个时间都在后端重新校验（工作时段、可活动窗口、免打扰、活动类型），不因「是 Agent 算的」就放行。验收场景里「把建议时间改成午休时段再保存」会被 422 拒。
2. **模型密钥只在后端**：`QWEN_API_KEY` 从后端环境变量读取，不进前端、不进镜像、不进 Git。
3. **不越权**：工具从 ContextVar 取当前用户，签名里没有用户参数；`/agent` 入口在建流前就做登录校验，未登录返回 401 且不建立 SSE 流。
4. **无医疗建议**：提示词明确禁止诊断、治疗、用药、运动处方类内容。

## 数据流图

```
React 页面
  -> CopilotKit / AG-UI 交互层（前端 Runtime 8787）
  -> Python 后端 Agent 接口（POST /agent，建流前鉴权）
  -> Microsoft Agent Framework（只读工具）
  -> 后端业务服务层（唯一写入入口：校验 + 落库）
  -> 返回建议或状态
  -> React 更新页面
```
